# G-ARCH-STYLE-01 统一视觉母版

## 1. 用途

本母版适用于G-01至G-23全部架构图。每张图的具体提示词必须继承本文件，不得自行改变语义色、线型、主字体风格或画布比例。

## 2. 画布与版式

- 16:9横版，目标为1900×1080或更高分辨率，适合A4 Word正文按约15.8厘米宽插入。
- 白色或极浅灰背景，四周保留充足安全边距。
- 二维扁平、企业技术白皮书信息图，不使用透视。
- 顶部仅保留小型图号，不在图片内放长标题；中文图名使用Word图题呈现。
- 主阅读方向固定为从左到右或从上到下；模块严格对齐，箭头尽量不交叉。
- 单图控制在8至12个主要节点；复杂内容通过分组框和图外节点说明表达。

## 3. 语义色

| 语义 | 颜色 | 用途 |
|---|---|---|
| 用户、浏览器、前端 | 浅蓝 `#DCEBFA` | User、Web UI、页面与交互 |
| API、控制面、业务服务 | 蓝灰 `#D9E2EC` | APISIX、Go API、领域服务 |
| Kafka、Flink、异步管道 | 低饱和橙 `#F4DFC3` | Topic、Job、Event、DLQ |
| 数据库、缓存、对象 | 灰绿 `#DDE9DF` | PG、CH、OS、Nebula、Redis、MinIO |
| 安全、权限、运维、证据 | 紫灰 `#E4DEEE` | IAM、Audit、SLO、Backup、Evidence |
| 风险、失败、阻断 | 低饱和红 `#F3D6D4` | 只用于少量风险或失败标记 |

单图最多使用五类主色；低饱和红只作为风险标记，不作为常规模块底色。

## 4. 节点与文字

- 节点使用统一圆角矩形，细蓝灰描边，无阴影或仅有极轻微平面阴影。
- 节点标签优先为编号加短英文，例如 `N01 Web UI`、`N05 Kafka`。
- 英文产品名必须准确：`APISIX`、`PostgreSQL`、`ClickHouse`、`OpenSearch`、`NebulaGraph`、`Redis`、`MinIO`、`Kafka`、`Flink`。
- 中文标签每项不超过8个汉字、最多两行；不生成解释性段落和小字号脚注。
- 文字只能来自逐图白名单，不得增加宣传语、随机缩写、厂商Logo或未确认组件。

## 5. 连线

| 线型 | 图内短标识 | 含义 |
|---|---|---|
| 深蓝实线箭头 | `REQ`或`CMD` | 同步请求或命令 |
| 蓝灰点划线箭头 | `QUERY` | 查询与读取 |
| 橙色虚线箭头 | `EVENT` | 异步事件、消息、投影 |
| 绿色双线或细实线 | `OBJECT` | 对象、manifest或证据引用 |
| 红色短虚线 | `FAIL` | 故障、阻断或回滚方向，仅专项图使用 |

不使用无语义双向箭头。每条边必须在逐图白名单中出现；不允许模型自行补充“合理连线”。

## 6. 全局架构禁止关系

- Web UI不得直接连接任何数据库、Kafka、Flink或MinIO。
- HTTP请求不得同步写入PostgreSQL、ClickHouse、OpenSearch和NebulaGraph多个存储。
- Probe不得直接写PostgreSQL。
- Redis不得表现为权威业务事实库。
- Kafka不得表现为页面直接查询的数据源。
- Flink不得参与用户、权限、规则审批、工作流等普通控制面CRUD。
- OpenSearch与NebulaGraph不得反向覆盖PostgreSQL权威状态。
- 知道MinIO对象key不得等同拥有下载权限。
- TARGET态的Outbox、mTLS、HA或DR不得画成AS-IS已验证能力。

## 7. 全局输出禁止项

- 不使用3D、等距透视、霓虹、赛博朋克、发光、电路板、复杂纹理、机房照片或云朵装饰。
- 不使用云厂商Logo、数据库圆柱堆叠、人物照片、设备照片或品牌商标。
- 不虚构吞吐量、时延、服务器数量、SLA、节点数量、容量和容灾等级。
- 不生成白名单外中文、随机英文、错拼产品名、水印或页码。

## 8. 全局验收

1. 30秒内可以识别图的唯一主问题和主阅读方向。
2. 节点、分组、文字和连线全部来自白名单。
3. 命令、查询、事件、对象和失败语义没有混淆。
4. 控制面、数据面、权威状态、投影和对象边界正确。
5. 缩放到Word正文宽度后，编号、短标签和箭头仍可辨认。
6. 同一组件在所有图片中的颜色、形状和拼写一致。
7. 不把目标设计、仓库Manifest或历史证据表现成当前生产已验证结果。
