# 高风险操作验收剧本(SUB-FS-12 销项证据)

- 依据:`doc/03_review/专家深评整改清单.md` SUB-FS-12(高风险操作缺 RBAC + audit + UI feedback 三联验收)、
  `doc/07_alignment/统一权限体系设计方案-2026-08-18.md` ADR-5(审计闭环)。
- 三联定义:①RBAC(允许/拒绝按 scope 判定)②审计落库(允许与拒绝都留痕,审计页可查)③UI 反馈(审计页/操作结果可见)。
- 状态:2026-08-18 live 验收通过(白名单/pcap/规则/模型四类高风险操作)。

## 1. 剧本(每操作四断言)

对每个高风险操作执行四断言:
1. **允许**:持有契约 `required_scope` 的主体(admin)→ 业务成功(2xx)。
2. **拒绝**:无该 scope 的主体(viewer)→ 403,响应体带 PERMISSION_DENIED/FORBIDDEN 与所需 scope。
3. **审计落库**:`audit_logs` 出现对应行(允许 success / 拒绝 denied,`detail.required_scope` 或 resource_type 正确)。
4. **审计页可查**:`GET /api/v1/audit/logs?action=<ACTION>` 返回该行(admin 凭 `audit:read`)。

| 高风险操作 | 端点 | 所需 scope | 允许审计 action | 拒绝审计 action | live 结果 |
|---|---|---|---|---|---|
| 白名单创建 | POST /api/v1/whitelist | alert:write | whitelist-create (success) | WHITELIST_ACCESS_DENIED (denied) | 允许 **201**(entry 9b5c8ae6…);拒绝 **403** alert:write required;两类审计行均落库+审计页 200 可查 |
| 白名单归档(清理) | DELETE /api/v1/whitelist/{id}?expected_revision= | alert:write | whitelist-archive (success) | WHITELIST_ACCESS_DENIED (denied) | 允许 **200**(status=archived,version=2,验收数据已清理) |
| PCAP 下载/取证 | GET /api/v1/pcap/download/{key}、POST /api/v1/pcap/presign | pcap:download | PCAP_DOWNLOAD (success) | AUTH_PERMISSION_DENIED (denied) | 拒绝路径 live 以 GET /pcap/stats 代验(同 requirePermission 判定链):viewer **403** `Permission denied: pcap:read required`,审计行 AUTH_PERMISSION_DENIED/pcap/pcap:read/denied 落库+审计页可查;admin 同端点 **200** |
| 规则发布 | POST /api/v1/rules | rule:write | RULE_PUBLISHED (success) | RULE_ACCESS_DENIED (denied) | 拒绝 **403** `permission denied: rule:write required`;拒绝审计经 audit.logs→audit-materializer→audit_logs,审计页 2 行可查;允许路径业务发布为破坏性操作未在 live 执行(代码路径已审计落库,如实登记) |
| 模型激活 | POST /api/v1/models/{id}/versions/{v}/activate | model:activate | MODEL_VERSION_ACTIVATE (success) | RULE_ACCESS_DENIED (denied) | 拒绝 **403** `permission denied: model:activate required`(授权先于资源锁定,SUB-FS-12 修复后 viewer 不再触发 500);拒绝审计落库可查;允许路径不翻转生产模型(如实登记) |

## 2. 本轮落地的代码修复(闭合 SUB-FS-12)

1. **拒绝留痕(ADR-5)**:forensics `requirePermission` 拒绝时同步写 `AUTH_PERMISSION_DENIED` 审计行(best-effort,403 语义不因审计失败改变);白名单 `requireWrite/requireRead` 拒绝写 `WHITELIST_ACCESS_DENIED`;rule-manager `writeError` 权限拒绝路径发 `RULE_ACCESS_DENIED` 审计事件。
2. **授权顺序修复**:`ModelService.ActivateModelVersion` 原实现先 `SELECT FOR UPDATE` 后 `checkPermission`,无 scope 调用者得到 500;现拆 `checkScopePermission` 前置判定,viewer 得 403。
3. **审计物化器上线**:`cmd/audit-materializer` 部署(traffic-analysis ns,Kafka `audit.logs` → PG `audit_logs`,消费组 `audit-consumer` 按 ACL 计划授权),规则/模型拒绝审计由此闭环。
4. **OIDC 回退补齐**:forensics-service 与 rule-manager 修复 nil OIDC provider(与 alert-service 同源缺陷),KC 访问令牌经 JWKS 回退可通行(此前 401 AUTH_1003)。
5. **环境修复(如实登记)**:traffic-ui 客户端密钥两次轮换(public/confidential 切换触发)→ k8s/external-secrets 源与 KC 侧同步;补建 `model_action_execution_inbox`、`deployment_event_projection`、`deployment_state_projection`、`model_feedback_inbox` 三列、`model_action_outbox`、`whitelist_rule_projection`、`rule_update_applied_acks`、`rule_version_rollback`、`model_rollback_requests` 等表/列;`model_action_jobs` 加法列(event_id/revision/result/error/trace_id);forensics minio 凭证 secret(accesskey=admin)。

## 3. UI 反馈

- 审计页 `AuditLogPage`(路由 audit-log,`audit:read`)经 `/api/v1/audit/logs` 展示上述 deny/allow 行:action=WHITELIST_ACCESS_DENIED / AUTH_PERMISSION_DENIED / RULE_ACCESS_DENIED / whitelist-create 均可过滤查询(live 200)。
- 拒绝响应统一 PERMISSION_DENIED/FORBIDDEN + required scope,前端全局 403 处理可见。
- 允许路径(白名单创建/归档)返回 receipt(id/status/version),前端可展示操作结果。

## 4. 复跑方法

```
# viewer = admin-cli token(无 traffic 角色 → viewer);admin = traffic-ui OIDC 令牌
curl -X POST .../api/v1/whitelist -H "Authorization: Bearer $VIEWER" ...   # 403 alert:write required
curl .../api/v1/pcap/stats -H "Authorization: Bearer $VIEWER"              # 403 pcap:read required
curl -X POST .../api/v1/rules    -H "Authorization: Bearer $VIEWER"        # 403 rule:write required
curl -X POST .../api/v1/models/{id}/versions/{v}/activate -H "Bearer $VIEWER" # 403 model:activate required
curl ".../api/v1/audit/logs?action=WHITELIST_ACCESS_DENIED" -H "Bearer $ADMIN" # 200,含 denied 行
```
