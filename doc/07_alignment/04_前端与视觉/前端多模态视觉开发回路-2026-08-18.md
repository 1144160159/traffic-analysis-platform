目的:让 DeepSeek 类编码智能体在**前端开发**中具备"看见页面"的能力,形成
"渲染 → 看见 → 修复 → 再渲染"闭环。本文件记录环境事实、已建成工具与可用插件组合。

## 2. 已建成工具:`web/ui/scripts/visual-inspect.cjs`

```bash
cd web/ui
npm run dev                                   # 或直接 ./node_modules/.bin/vite
node scripts/visual-inspect.cjs [baseURL] [outDir] [--ocr]
# 默认 http://127.0.0.1:5173,/tmp/ui-shots
```

每个页面产出三通道证据:

| 产物 | 消费方 | 说明 |
|---|---|---|
| `<name>.png` | 视觉模型(read_image) | 像素级审阅:布局/配色/遮挡/断点 |
| `<name>.dom.txt` | 文本模型(deepseek-v4-pro 首选) | 完整可见文本,干净无噪声 |
| `<name>.ocr.txt` | 文本模型兜底 | tesseract(chi_sim+eng);表格密集页噪声大,仅兜底 |

覆盖页面:login、任务管理、调度管理、任务编排、运行监控、分析报告、调度资源、
任务定义详情(1440×900)+ 运行监控移动端(390×844)。

首次视觉检查发现的真实问题(2026-08-18):
- 分析资源页在 dev(mock)环境呈 `调度资源读取失败/重试` 错误态(401 未 mock),
  属预期 fail-closed,但提示前端需为资源页补 MSW handler 或明示"mock 环境不可用"。

## 3. "给 DeepSeek 增加多模态"的插件组合(按使用场景)

DeepSeek 官方 API 无视觉端点,多模态必须由**客户端/工具侧**提供"眼睛":

| 场景 | 推荐 | 说明 |
|---|---|---|
| 本仓库开发(本会话) | `scripts/visual-inspect.cjs` + 视觉模型 `read_image` | 已建成;当前会话需切换到图像输入模型即可闭环 |
| 本地客户端 + 私有化 DeepSeek | **Page Assist**(浏览器扩展) | 接 Ollama/OpenAI 兼容端点;页面上下文+截图喂视觉 |
| 多模型工作台 | **Cherry Studio** | DeepSeek 负责推理/代码,视觉模型(如 Qwen-VL)看截图 |
| VS Code 智能体 | **Cline / Roo Code** | 内置浏览器工具截图;配视觉模型即视觉前端开发 |
| 自托管 Web | **Open WebUI** | 视觉管线 + 模型路由 |
| MCP 工具化 | **@playwright/mcp** | 把浏览器导航/截图暴露给任意 MCP 客户端;与视觉模型组合 |

组合原则:**DeepSeek 当"脑"(推理/改码),视觉模型当"眼"(读 PNG),
Playwright 当"手"(渲染/截图/点击)**。三个组件解耦,任何一方可替换。
