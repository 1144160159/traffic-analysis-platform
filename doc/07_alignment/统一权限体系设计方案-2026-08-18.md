## 4. 目标架构(设计)

### 4.1 总体原则
1. **单一令牌模型**:全站唯一 API 凭证 = Keycloak 访问令牌;废除双 token。
2. **单一租户事实**:租户来自 token claim,不来自可伪造的请求头。
3. **三层防御**:网关(认证+限流)→ 服务共享中间件(租户绑定 + scope 判定)→ 仓储(WHERE tenant_id 强制过滤)。任一层失效不导致越权。
4. **契约驱动**:角色映射、scope 目录、逐操作授权全部由 contracts/authz 契约文件驱动,代码只做解释器。
5. **零信任/失败关闭**:缺 claim、映射失败、契约缺失一律拒绝,不降级放行。

### 4.2 关键决策(ADR)

**ADR-1 令牌模型:统一 Keycloak 访问令牌**
- 理由:Keycloak 是既有 IdP;access token 已含 realm/client 角色(实测);网关已可校验;避免双签机制。
- auth-service 应用 HMAC token 废弃(保留兼容窗口):/me、/logout 等端点改走共享中间件(Keycloak token)。
- 前端删除 appTokenPrefixes 清单,httpClient 只带一个 token。
- 服务侧统一接入 `internal/common/authz` 共享中间件(JWKS 校验 + claims 解析),逐服务替换自研校验。

**ADR-2 租户事实**
- Keycloak 增加 `tenant_id` 声明映射器(来源:用户属性 tenant,缺省 default;跨租户管理员走显式 `admin:cross-tenant` 豁免)。
- 共享中间件强制:`token.tenant_id == X-Tenant-ID`(相等);不等或缺失 → 403。
- 仓储层审计:所有租户表查询强制 `WHERE tenant_id = ctxTenant`,静态审查 + 集成测试断言。

**ADR-3 角色映射契约化**
- 新增契约 `contracts/authz/oidc-role-map.v1.json`:`{ "traffic-admin": {"internal_role":"admin"}, ... }`,与 Keycloak 实际角色由发布流程校验(ensure-keycloak-traffic-ui-client.sh 扩展为契约源)。
- 角色来源改为 **access token(JWKS 校验)**;ID token 仅用于身份断言(nonce/sub)。
- runtime 测试锁定:契约 ↔ DefaultRoleScopes ↔ Keycloak 角色三方一致。

**ADR-4 授权判定合一(后端权威)**
- 后端:每操作按 m10 契约判定(共享中间件 + 操作注册表);admin 角色授权语义统一——**给 admin 补发 `admin:*` 通配**(契约 counts 同步更新),同时保留 HasRole('admin') 豁免作为纵深。
- 前端:路由可见性与按钮 enabled 状态 = 服务端 permissions(/me)+ allowed-actions 投影;前端不再自行推断业务规则。

**ADR-5 审计闭环**
- 高风险操作(白名单/规则发布/模型激活/PCAP 下载/权限变更)统一:允许→审计落库(analysis_history/audit 表)→ 审计页可查;拒绝→403 留痕。
- 权限变更事件进 `user.events.v1`(既有 topic),与审计页联动。

**ADR-6 机器凭证**
- API Token 纳入统一模型:token → 绑定 tenant+scopes 子集,经同一共享中间件(区分 human token vs api token 类型),审计 actor=api-token。

### 4.3 组件职责

```
浏览器 ──(Keycloak OIDC 登录)──► 应用(单一 token)
   │ api 请求(Bearer KC token + X-Tenant-ID)
   ▼
APISIX(认证:OIDC bearer_only;限流;匿名白名单仅登录链)
   ▼
internal/common/authz 共享中间件(每服务统一接入):
  1) JWKS 验签 2) tenant 绑定校验 3) role→scope 契约解释 4) 操作级判定
   ▼
服务业务逻辑(仓储层强制 tenant 过滤)
   ▼
审计/事件(user.events.v1 + 审计表)
```

## 6. 迁移计划(加法式,不静默改 base 链)
1. P0 先行:修角色落地(access token 角色)+ Keycloak tenant mapper + 共享中间件只对 analysis-service 灰度上线(影子模式记拒绝,观察无回归后强制)。
2. P1:双 token 废除(前端单 token;auth 端点迁移),per-route 清单删除;admin 补发 admin:*。
3. P2:契约解释器全量接入各服务;审计三联销项。
4. P3:G06-G09 正式验收;旧 HMAC 令牌兼容窗口到期后下线。

## 7. 验收标准
- 契约不变式逐条可测(租户隔离/每操作必有 scope/对象查找租户化/字段白名单/密钥不暴露);
- 越权用例矩阵:跨租户读、伪造 X-Tenant-ID、无角色、过期 token、缺 claim → 全部 401/403(fail-closed);
- admin 用户 OIDC 登录 → /me roles=[admin]+permissions 含 admin:*;前端路由/按钮与后端一致;
- 高风险操作审计闭环三件套可查。
