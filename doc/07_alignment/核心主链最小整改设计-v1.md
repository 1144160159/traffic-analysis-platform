## 0. 整改裁决:一句话

详细设计冗余的根因是"用 9724 行覆盖 M00-M13 全量业务";整改方式不是重写,而是**冻结一个核心卷 + 悬挂其余轨道**。核心卷只回答一个问题:

> 一条最小统一分析任务链,如何产出可复算的"预警准确率≥95%、误报率<5%"评估结果并形成报告?

### 0.1 架构不变式(不可裁剪)

**整体业务架构的"统一任务调度"形态不变**。整改只裁剪业务范围,不改变执行形态:

```text
AnalysisTaskDefinition
  -> AnalysisPlanRevision(不可变,execution_spec_sha256)
  -> ScheduleRevision / TriggerInstance(window|cron|event|on-demand)
  -> MaterializeAnalysisTaskAtomic -> AnalysisTask + AnalysisRun
  -> RunSubscription + PlanReady
  -> S1 采集 -> S2 会话/特征 -> S3 加密识别 -> S4 恶意检测
  -> Reconcile -> S5 机器摘要(RunClosureManifest + MachineAnalysisSummary + EvidenceManifest 同事务)
  -> Run 唯一终态 -> current-run 投影
  -> 异步人读报告(独立 ReportState)
```

- 调度权威模块(Definition/Plan/Schedule/Trigger/Task/Run/Stage/Receipt/MachineSummary)一个都不能裁;AUTO/MANUAL 正交裁决、五段业务投影、RunScopeRouter、Reconcile、唯一终态全部保留原文案语义。
- **自动执行与人工前端选择都是主业务链的执行环节**:AUTO_DEFAULT 与 MANUAL_CUSTOM 只决定计划参数来源,二者经同一 PlanCompiler 冻结、同一 MaterializeAnalysisTaskAtomic 物化、同一执行器链与同一 Run/报告闭环;核心卷必须同时交付"默认方案自动触发"与"人工选择探针/特征/识别模型/检测模型/阈值的自定义方案触发",不得把 MANUAL_CUSTOM 悬挂到后续轨道。
- **评估与报告同样是 Run**:95%/5% 复测 = 一条 `SourceKind=PCAP_REPLAY` 的离线 Run(同候选/同 plan hash/同执行器链,评估结论写入机器摘要);报告 = 该 Run 终态后经 `RequestHumanReportAtomic` 异步派生。不存在架构外的评估脚本或报告旁路。
- 裁剪的只是**业务域**:APT 战役/攻击链/GNN/CEP、四源融合、完整取证、PDF 复杂模板。

## 1. 范围收敛(明确排除,不阻塞核心)

| 类别 | 处置 |
|---|---|
| APT 战役/攻击链/GNN/CEP | <code>EXCLUDED_FOR_CORE</code>,M07/M09 整体移入后续轨道卷 |

## 2. 执行器最终清单(数量裁决)

调度权威骨干(不可裁剪,analysis-service 一个部署单元)+ 运行期计算/外围执行器 **10 个**;上游前置 2 个(不进 Run DAG)。所有计算执行器的 receipt 都必须绑定 `tenant/task/run/execution_spec_sha256`,不存在脱离 Run 的"裸执行"。

### 2.1 调度权威骨干(P0 模块,架构不变式)

| 模块 | 职责 |
|---|---|
| Definition/Plan/Schedule Authority | 定义、不可变计划修订、调度修订、治理头 CAS(maker/checker) |
| Trigger + MaterializeAnalysisTaskAtomic | 四种触发归一为同一物化事务,精确重放/完整性冲突 |
| Queue & Resource Allocator + AdmissionReservation | 公平队列、配额、容量准入 |
| Lease & Fencing + Inbox/Outbox + Durable Orchestrator | 认领/隔离、可靠投递、receipt 驱动推进/取消/重试 |
| RunScopeRouter | 共享 base 流按 ACK 订阅派生 0..N run envelope |
| Receipt & Reconciler + Result Finalizer | count/watermark 对账、机器摘要、唯一终态 |
| Query/API/Audit + 只读运行监控最小页 | 查询与审计(UI 八页不进入核心) |

## 3. 特征池→阶段映射(《统一PCAP特征池与在线覆盖契约》)

原则:每类特征只有一个在线权威阶段;在线与离线同一派生实现保证 parity;未执行模态必须显式缺失,禁止伪造全零。

| 特征类别(数量) | 采集/聚合阶段 | 执行器 | 产出载体 | 在线/离线边界 |
|---|---|---|---|---|
| 85 安全流标量:基础规模 22/包长 16/IAT 19/payload 长度 8/active-idle 10/速率+TCP 标志 10 | **S1 采集期流聚合**(基础行为层 B) | Rust flow_table 聚合 | FlowEvent(已含 packets/bytes fwd/bwd、pktlen、iat、active/idle、tcp_flags、tos) | 在线真源;离线由冻结 PCAP 回放重算 |
| 17 序列列(前 64 包) | **S1 采集期有界分段**(64 包后 `flow_segment_index` 递增,不静默截断) | Rust 流分段 | 经 FlowEvent→**S2 FeatureSeq** | 同上 |
| 预算化深层(Payload 4096B 前缀/L4 2048B 前缀/256 维直方图/TLS record/handshake/QUIC) | **S1 预算调度 deep tier**;未调度 → 显式 `modality_missingness_mask` | Rust 预算调度器 | FlowEvent 扩展 + 缺失性掩码 | 只有调度到 deep tier 才物化 |
| 8 TLS/QUIC 结构(tls_*_seq、client/server_hello、quic_*) | **S1 采集期解析 + S3 加密识别** | Rust parser → EncryptedRecognizer | FeatureFingerprint(L3)→ RecognitionOutcome | 识别阶段产 typed outcome,不直接判恶意 |
| JA3/JA4/SNI/证书指纹 | **S3 加密识别** | EncryptedRecognizer | FeatureFingerprint | 同 S3 |
| 7 派生列(initiator_relative_direction_seq/signed_packet_length_seq/burst_*/payload_presence_fraction/missingness_mask) | **S2 特征提取确定性派生** | Flink feature(与离线共用同一纯函数实现) | FeatureStat/FeatureSeq 派生字段 | 离线在线 parity 由同实现保证 |
| 10 在线窗口上下文 | **S2 特征提取 1 秒窗口** | Flink feature 窗口 | FeatureStat 窗口字段 | 仅在线;不改变 143 列契约 |
| 4 基础导出(packet_count_stored/port_a/port_b/app_hint) | **S1 导出辅助** | Rust | FlowEvent 审计字段 | 审计/诊断;**默认禁止入模** |
| 17 审计/溯源列 + 6 标签列 | **评估执行器(离线外部控制面)** | 冻结数据集 manifest | 143 列 CSV/Parquet | 在线禁止猜测标签 |
| 守恒式 | 每阶段 receipt 复核 | Reconcile | parsed=recognized=base_featured;observed_flows=pipeline_results;deep_selected+deep_deferred=records | 阶段对账 |

关键裁决:现有 FeatureStat 的 `extra` 数组 + FeatureSeq 是 85 标量/17 序列在 L2 的载体;缺失列必须经 `missing_fields/missing_reason` 显式声明,而不是默认值。

## 4. 设计模式映射(ENG-SW-002,PR 级 ADR)

| 执行器/对象 | 模式 | selected_form | 关键边界 |
|---|---|---|---|
| DefaultPlanResolver / CustomPlanResolver | Strategy | GOF | 只产 NormalizedPlanIntent,不承担触发/容量 |
| SourceExecutor 接口 + Probe/PCAP 适配 | Adapter | GOF | 转换错误/identity/time/receipt;不裁决 Run 终态 |
| Sessionization/FeatureExtraction/Detection | Pipeline | PROJECT_ADAPTATION | 常驻共享拓扑;逻辑准入≠为每 Run 起 Job |
| EncryptedRecognizer / SelectedThreatDetector | Strategy | GOF | 相同合同、exact-set 显式选择、不冒充状态机 |
| DetectionAggregate | 聚合器 | DIRECT | 不允许命名 Facade/Manager 装饰 |
| MachineSummaryFinalizer / EvaluateRunClosure | Command+State | NATIVE_LANGUAGE | 纯函数真值表 + 唯一终态 CAS |
| Orchestrator/Receipt/Outbox | PROJECT-ADAPTATION | — | transactional outbox + durable workflow;禁止用 Observer 内存解释 Kafka |
| HumanReport worker | Adapter + 对象权威 | PROJECT_ADAPTATION | 独立 ReportState,失败不回退 Run |

禁止项(照抄主链裁决负例):按 plan_source 拆双栈;Singleton 保存租户模型;Chain of Responsibility 跳过 required node;Template Method 跨 Flink 继承层。

## 7. 执行顺序(调度骨架先行,再聚焦业务)

1. **先冻结调度权威骨架**(架构不变式):ATC-GOV(统一 BF/Task/Plan/Run 治理合同)→ ATC-CONTRACT(Proto/API/Topic/状态/错误合同)→ ATC-DATA(PG expand schema)→ ATC-AUTH(Task/Plan/Run 权威事务)→ ATC-SCHED(Schedule/Queue/Lease/Fencing)→ ATC-ORCH(DAG、receipt、reconcile、cancel);生成器分配核心卷 PR ID(复用既有 ATC 列车,不新建 ID 体系);
2. **ATC-CUSTOM(核心列车,与 AUTO 同拓扑)**:CustomPlanResolver(人工覆盖项→NormalizedPlanIntent+selection_origins)、服务端 preflight、maker/checker 审批链、前端三步向导 custom 分支;人工选择只进入本次 plan revision,不改全局 active 指针;
3. **评估器以离线 Run 的形态先行**(95%/5% 的尺子):PCAP_REPLAY Run 接评估阶段,签字公式、四类样本、label-schema 校验复用已具备基础;
4. PCAP 回放 + Session/Feature 改造(按第 3 节特征池映射落地 exact-set,ATC-FEATURE);
5. EncryptedRecognizer + Rule/Behavior exact-set + DetectionAggregate(ATC-RECOGNITION/ATC-DETECTION,每输入×required detector typed outcome);
6. PlanReady/Reconcile/MachineSummaryFinalizer 权威闭环(ATC-SUMMARY);
7. 机器摘要 + 单一模板人读报告(ATC-HREPORT,异步派生不改 Run 终态);
8. 同候选四象限(实时/离线 × 加密/非加密)以 Run 为单位复算 95%/5% + 报告输出。

完成定义:调度权威骨架 + 上述 7 步的函数合同卡、G01/G02(以及能执行的 G03/G04)证据齐备;G05-G09 保持 BLOCKED 如实标注,不宣称闭环。任何"跳过调度中心直连执行器"的实现都被视为负例拒绝。
