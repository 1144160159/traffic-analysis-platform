## 5. 节奏与风险

- **建议节奏**:P0+P1 先行(纯后端,可完全本地验证);P2 与 P3 可并行(不同目录:analysis-service vs rust/java);P4-P6 顺序依赖。
- **风险**:① 真实 PG/CH/Redis 环境未到位 → P0/P1 的 G04 用测试容器,不影响 G01/G02 推进;② Windows Chrome 隧道(agent.md §5)不可用 → P6 的 G06 标 BLOCKED;③ 探针硬件窗口(10×100Gbps)不属于本计划(核心链验收不含性能容量)。
- **停止条件**:任何阶段出现未决 P0 语义/安全/恢复 veto → 该阶段保持 BLOCKED,不以下一阶段进度掩盖(总则 §13)。
