**边界铁律**(单一职责):
- 调度中心 = 命令、编排、权威事实、outbox/回执;**绝不包含** pcap 解析、流聚合、特征计算、检测推理。
- 探针/回放执行器 = 采集与对象回放(Rust,发生地在探针)。
- Flink 常驻作业 = 会话化/特征/识别/检测(分析计算组件)。
- gateway = 传输与路由(探针命令路由、回执回流),不做业务裁决。

## 2. 模式映射(EIP / PoEAA / GoF)

| 本项目组件 | 模式 | 依据与要点 |
|---|---|---|
| 触发→物化事务(台账+唯一约束+同事务插 Task/Run/回执) | EIP Idempotent Receiver + PoEAA Unit of Work | 同 identity 同 hash 重放同句柄;异 hash 409 |
| Run 生命周期状态机(state 包六轴/五阶段) | EIP Process Manager | 状态机独立纯函数;闸门/终局由管理器驱动 |
| StageGateLoop/StageDispatcher/Reconciler | EIP Process Manager(权威) | SKIP LOCKED+CAS,多副本安全领单 |
| RunScopeRouter(Flink) | EIP Content-Based Router | 租户+窗口+fencing 匹配,0..N 派生,base 流保持无归属 |
| PcapReplayAdapter/PlanResolver/Detector | GoF Adapter / Strategy | 协议转换;可替换策略族;不裁决终态 |
| RunEventRelayer(outbox→Kafka) | PoEAA Transactional Outbox | 业务事务与消息发布同事务;中继幂等发布+退避 |
| ReceiptApplier(inbox 去重+quarantine) | EIP Idempotent Receiver | event_id 去重;确定性非法消息同事务隔离不重投 |
| run_id/fencing_token/operation_id 贯穿各组件 | EIP Correlation Identifier | 跨进程关联执行上下文;fencing 防旧回执 |
| Kafka topic(analysis.* / probe.control.v2) | EIP Message Channel | 合同目录(kafka-topic-catalog)为唯一真源 |
| PG inbox/outbox/history/ledger | PoEAA Repository + Data Mapper | 仓储按聚合边界组织;读写分离(Query 侧 RunView) |

## 3. 七大设计原则审计(对当前实现)

| 原则 | 达标 | 违规与整改 |
|---|---|---|
| 单一职责 SRP | 部分 | 已整改:回放执行迁出调度中心(Rust probe);此前 in-process 回放=调度与分析混部(违反) |
| 开闭 OCP | 部分 | `StageDispatcher.buildCommand` 按 SourceKind switch 扩展需改代码→**改注册表**(整改项 1) |
| 里氏替换 LSP | 部分 | `SourceExecutor` 端口含 Cancel/Resolve,而适配器以占位("cancel-not-tracked"/UNKNOWN)敷衍→**收窄端口**(整改项 2) |
| 依赖倒置 DIP | 达标 | 端口全部面向接口:SourceExecutor/EventPublisher/ProbeCommandPublisher/TemplateLoader/RunReader;依赖由装配层(main)注入 |
| 接口隔离 ISP | 部分 | 同上,端口过宽强加无意义方法→收窄为 Dispatch-only;Cancel/Resolve 移为可选能力 |
| 迪米特 LoD | 达标 | service 只与仓储端口/发布端口交互;不穿透跨组件内部结构 |
| 合成复用 CRP | 达标 | 组合优于继承:ProcessFunction 包装路由核心、adapter 组合 publisher |

## 5. 原整改项清单

1. **OCP**:`StageDispatcher` 的 SourceKind→命令构造改为注册表(`map[string]SourceCommandBuilder`),新增 SourceKind 只注册不修改;未知 kind fail-closed。
2. **ISP/LSP**:`contract.SourceExecutor` 端口收窄为 `Dispatch` 单方法;`Cancel/Resolve` 从端口移除(保留为适配器具体能力,派发循环不使用);`StageDispatcher` 只依赖 Dispatch。
