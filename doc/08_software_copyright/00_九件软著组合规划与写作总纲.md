# 九件软件著作权组合规划与写作总纲

## 1. 交付数量

正式登记材料按 **9件软件作品、9篇主说明书** 编写。每篇主说明书同时承担“相关文档鉴别材料”和研发事实说明的作用，不再为同一作品并行编写内容重复的设计说明书、用户手册和操作手册。

另维护组合总纲和交叉去重检查表两篇内部文档。因此：

```text
对外登记作品：9件
正式作品说明书：9篇
内部组合管理文档：2篇
内容文档总数：11篇
加README索引后的Markdown文件数：12个
架构图：10组（组合1组 + 每件作品1组）
```

## 4. 写作事实分级

每项功能在进入正文前必须标注来源：

| 标记 | 含义 | 可否写入“已实现功能” |
|---|---|---|
| `CURRENT_CODE` | 当前冻结候选中存在且可构建 | 可以 |
| `CURRENT_RUNTIME_EVIDENCE` | 当前候选有真实运行证据 | 可以，并引用证据时间和环境 |
| `HISTORICAL_EVIDENCE` | 历史候选曾验证 | 只能写历史记录，不得推导当前状态 |
| `DESIGNED_NOT_IMPLEMENTED` | 详细设计已有方案但未落代码 | 不可以，只能放“后续规划” |
| `EXTERNAL_ACCEPTANCE_PENDING` | 需第三方或现场验收 | 不可以写已达标 |

## 5. 架构图规则

1. 组合图只表达九件作品之间通过API、事件或对象契约协作。
2. 单篇架构图只把本作品内部模块放入实线边界；其他作品一律标为“外部系统/共享依赖”。
3. `proto/traffic/v1`是共享契约，不归任何一篇独占。
4. PostgreSQL、Kafka、ClickHouse、OpenSearch、NebulaGraph、Redis、MinIO是运行依赖，不作为软件作品本身。
5. 图中不得写“95%准确率”“CNAS通过”“10×100Gbps”等未闭环结论。
6. 图源、SVG、正文引用必须使用相同图号和版本。

## 6. 申报材料形成顺序

```text
作品组合冻结
  → 源码唯一归属与共享依赖清单
  → 每件clean candidate/tag
  → 独立构建与真实功能核验
  → 九篇说明书成稿
  → 源程序与文档鉴别材料生成
  → 权属/SBOM/重复检查
  → 名称/版本/日期/署名六方一致性检查
  → 单件评审
  → 九件交叉评审
  → 在线申请表与最终签章
```

## 7. 总体完成清单

- [ ] 九件作品名称、简称和版本冻结。
- [ ] 每个生产源文件仅归属一件作品。
- [ ] 共享代码和自动生成代码从专属代码样本中排除。
- [ ] 九件均有独立入口、构建命令、制品hash和运行说明。
- [ ] 九篇均达到计划篇幅且不是替换标题式复用。
- [ ] 十组架构图与冻结源码边界一致。
- [ ] 每篇至少三条核心旅程和一条失败恢复旅程有真实证据。
- [ ] 申请表、代码页、文档页、制品和界面中的全称/版本一致。
- [ ] 权属、合作/委托/职务开发和第三方依赖闭合。
- [ ] 未实现功能和未验收指标均未包装成当前成果。

## 8. 推荐写作批次

| 批次 | 内容 | 建议工期 | 退出条件 |
|---|---|---:|---|
| W0 | 九件边界、名称、版本、权属和源码唯一归属冻结 | 5–7个工作日 | 一文件一作品、共享依赖和候选tag确定 |
| W1 | SW-01、SW-02、SW-04数据采集/流处理/取证三篇 | 12–15个工作日 | 三篇独立制品和数据链路证据闭合 |
| W2 | SW-03、SW-05、SW-09领域服务三篇 | 12–15个工作日 | 权威事实、投影、鉴权和审计边界闭合 |
| W3 | SW-06、SW-07规则模型治理与训练两篇 | 8–10个工作日 | 服务端治理与训练客户端源码零交叉 |
| W4 | SW-08用户操作手册 | 8–10个工作日 | 同一候选、真实API和统一浏览器环境截图完成 |
| W5 | 九件交叉去重、排版、签章和申请表一致性复核 | 5–7个工作日 | 组合退出门全部为0 |

按一名主笔、两名模块作者、一名图表/排版和一名法务知识产权复核并行估算，总周期约40–50个工作日；若单人串行写作，应按80–100个工作日安排。该估算不包含补实现、补真实运行证据或权属争议处理时间。
