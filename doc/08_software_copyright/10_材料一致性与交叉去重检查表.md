# 九件软件著作权材料一致性与交叉去重检查表

## 1. 单件材料包

每件作品最终应形成：

- [ ] 当期在线申请表及签章页。
- [ ] 作品主说明书冻结PDF。
- [ ] 源程序鉴别材料冻结PDF。
- [ ] 软件全量源文件清单、顺序清单、SHA-256和总行数。
- [ ] clean commit/tag、构建命令、制品SHA-256和SBOM。
- [ ] 设计图、流程图、运行截图的原始文件和hash。
- [ ] 开发完成日期、发表状态和版本决策记录。
- [ ] 著作权人身份证明和权属证明。
- [ ] 第三方依赖、许可证、生成代码和共享代码排除清单。
- [ ] 研发、知识产权、项目负责人三方评审记录。

## 2. 名称与版本一致性

对申请表、签章页、源程序页眉、说明书页眉、封面、制品元数据、登录/CLI标题逐项比较：

- [ ] 软件全称完全一致。
- [ ] 简称完全一致；没有简称时按当期表单规则留空。
- [ ] 版本统一使用 `V1.0`，且不与运行制品版本冲突。
- [ ] 著作权人名称和署名完全一致。
- [ ] 开发完成日期可由commit、构建和测试记录追溯。
- [ ] 发表状态及首次发表日期/地点证据一致。

## 3. 一文件一作品检查

- [ ] 建立九件作品生产源文件全集。
- [ ] 任意两个作品的专属生产源文件交集为0。
- [ ] `proto/traffic/v1`、生成DTO、根POM、共享DDL作为共享依赖，不重复主张。
- [ ] Web源代码只进入SW-08。
- [ ] Rust PCAP采集和上传只进入SW-01；PCAP索引与取证只进入SW-04。
- [ ] 训练评估只进入SW-07；规则/模型发布权威状态只进入SW-06。
- [ ] Auth实现只进入SW-09；其他作品仅引用认证接口。
- [ ] 测试结果、证据JSON、缓存、Secret、二进制和第三方包不进入核心源代码量。

## 4. 代码和文档重复检查

- [ ] 对九套源码样本做文件hash交叉比较。
- [ ] 去除空白、import、许可证头和生成代码后做规范化克隆检测。
- [ ] 内部人工复核阈值设为5%；该阈值仅为项目风险控制，不是法定标准。
- [ ] 任意两件不得提交相同连续代码页。
- [ ] 任意两篇说明书不得共享整章功能叙述、同组截图或同一内部架构图。
- [ ] 不可避免的公共概念只保留简短接口说明，并明确“外部共享依赖”。
- [ ] 若只能通过改名、调换章节或替换截图区分，立即合并作品。

## 5. 实现真实性检查

- [ ] 正文每项功能都能映射到冻结候选的入口、模块或函数。
- [ ] 架构图节点能够映射到真实代码或明确外部依赖。
- [ ] 截图、日志、API/CLI示例来自同一候选和同一版本。
- [ ] planned路径和未执行PR没有写成已完成功能。
- [ ] 历史运行证据没有冒充当前候选证据。
- [ ] 性能、准确率、误报率、CNAS、HA/DR没有越界声明。

## 6. 鉴别材料排版检查

- [ ] 根据当期规则选择一般交存或例外交存。
- [ ] 一般交存的源程序为连续前30页、后30页；不足60页提交全部。
- [ ] 一般交存的文档为连续前30页、后30页；不足60页提交全部。
- [ ] 源程序页码连续，常规排版每页不少于50行。
- [ ] 文档页码连续，常规排版每页不少于30行。
- [ ] A4纵向、页眉、页码、字体和签章符合当期在线要求。
- [ ] 文件内无密钥、Token、真实个人信息和生产敏感配置。

## 7. 组合退出门

只有以下条件全部满足，九件组合才可进入正式申请：

```text
rights_blocked_count == 0
unfrozen_candidate_count == 0
cross_work_source_file_overlap == 0
duplicate_submitted_code_page_count == 0
name_version_owner_inconsistency_count == 0
unimplemented_feature_claim_count == 0
unsupported_metric_claim_count == 0
missing_primary_document_count == 0
missing_build_artifact_count == 0
```

任一项不满足时只修对应作品，不得通过改名或删除少量材料强行维持九件数量；必要时切换为六件保守组合。
